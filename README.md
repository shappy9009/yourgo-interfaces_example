# Пример работы с интерфейсами в Go

Учебный пример к занятию курса https://stepik.org/course/220674/promo.
Учимся, как с помощью интерфейсов отвязать код от конкретной реализации хранилища данных.

## Что в репозитории

- **model** - модели данных. Структура `Book` с конструктором `NewBook` (валидирует входные данные) и методом `String()`.
- **repository** - репозитории (или хранилища) книг. Два репозитория с одинаковым набором методов, `BookInMemoryRepository` хранит книги в памяти, `SecondMemoryRepository` - "имитация другого хранилища" (условно, база данных  или Excel, делает то же самое, но по-своему).
- **worker** - работяга, который создает и печатает книги, пользуясь репозиторием через интерфейс.

Используем **Dependency Injection**, где зависимость (репозиторий) передается воркеру снаружи через конструктор `New`, а не создается внутри него.

## Структура проекта

```
├── go.mod
├── main.go                  - точка входа: запускаем воркер с двумя репозиториями
├── model/
│   └── book.go              - модель Book
├── repository/
│   ├── inmemory.go          - репозиторий книг в памяти
│   └── bookinmemory2.go     - "другой" репозиторий с теми же методами
└── worker/
    └── worker.go            - воркер и интерфейс repo
```

## Запуск

Запускаем как обычно:

```bash
go run .
```

Ожидаемый вывод:

```
ID: 5, Название: Война и мир, Автор: Лев Толстой
ID: 10, Название: Преступление и наказание, Автор: Фёдор Достоевский
```

Первая строка напечатана воркером с `BookInMemoryRepository`, вторая - тем же воркером, но с `SecondMemoryRepository`.

## В чем идея

Воркер принимает не конкретный тип репозитория, а интерфейс:

```go
type repo interface {
	ByID(ID int) (model.Book, error)
	Add(b model.Book) error
}
```

Поэтому один и тот же `Worker` может работать с любым объектом, у которого есть эти два метода, хоть с репозиторием в памяти, хоть с репозиторием, который ходит в базу данных. Меняется реализация зависимостей, но не код воркера, он остается таким же.

Интерфейс выглядит именно так, как задумано в языке Go (это будем проходить подробно позже):

- Интерфейс объявлен **там, где используется**, то есть в пакете `worker`, а не в `repository` или `model`.
- Имя пишем с **маленькой буквы**, так как интерфейс неэкспортируется, он нужен только воркеру и не должен использоваться где-то еще.
- В интерфейсе **нет метода `Delete`**, воркер его не использует, а интерфейс должен требовать от зависимости **только то, что действительно нужно**.
